## 1. 동기(Sync) vs 비동기(Async) — 개념 이해

### 동기(Synchronous)란?

코드가 **위에서 아래로, 한 줄씩 순서대로** 실행됩니다.  
앞 줄이 끝나야 다음 줄이 실행됩니다.

```javascript
console.log("1번: 시작");
console.log("2번: 중간");
console.log("3번: 끝");

// 출력 순서:
// 1번: 시작
// 2번: 중간
// 3번: 끝
```

### 비동기(Asynchronous)란?

시간이 걸리는 작업(서버 요청, 타이머 등)을 **기다리지 않고 다음 코드를 먼저 실행**합니다.  
작업이 완료되면 그 결과를 나중에 처리합니다.

```javascript
console.log("1번: 시작");

setTimeout(() => {
    console.log("2번: 1초 뒤에 실행");
}, 1000);

console.log("3번: 끝");

// 실제 출력 순서:
// 1번: 시작
// 3번: 끝          ← 1초를 기다리지 않고 먼저 실행됨!
// 2번: 1초 뒤에 실행
```

### 왜 비동기가 필요한가?

| 상황 | 동기 방식의 문제 | 비동기의 해결 |
|------|-----------------|--------------|
| 서버에서 데이터 요청 | 응답 올 때까지 화면이 **멈춤(freeze)** | 응답 기다리는 동안 화면은 **정상 작동** |
| 대용량 파일 읽기 | 완료될 때까지 다른 코드 실행 불가 | 완료되면 알림(callback)만 받음 |
| 여러 API 동시 호출 | 하나씩 순서대로 → 오래 걸림 | 동시에 요청 → 빠름 |

> 💡 **한 줄 요약**: 비동기는 "기다리는 동안 다른 일을 한다"는 개념입니다.

## 2. 콜백(Callback) — 비동기의 원시적 해결책

**콜백**이란 "나중에 실행할 함수를 미리 전달해두는 것"입니다.

```javascript
// 콜백 함수의 기본 구조
function 시간이_걸리는_작업(완료되면_실행할_함수) {
    setTimeout(() => {
        const 결과 = "작업 완료!";
        완료되면_실행할_함수(결과); // 작업 완료 후 콜백 실행
    }, 2000);
}

시간이_걸리는_작업(function(결과) {
    console.log(결과); // "작업 완료!" 출력
});
```

### 콜백 지옥(Callback Hell)

콜백이 중첩되면 코드가 끔찍하게 복잡해집니다.

```javascript
// 콜백 지옥 예시 — 읽기도 어렵고, 에러 처리도 복잡합니다
사용자_정보_가져오기(userId, function(user) {
    레포지토리_가져오기(user.id, function(repos) {
        첫번째_레포_상세_가져오기(repos[0].id, function(detail) {
            기여자_가져오기(detail.id, function(contributors) {
                console.log(contributors); // ← 이미 4단계 중첩
            });
        });
    });
});
```

이를 해결하기 위해 **Promise**가 등장했습니다.

## 3. Promise — 콜백의 진화

**Promise**는 "미래에 완료될 작업의 결과를 담는 그릇"입니다.  
3가지 상태를 가집니다:

| 상태 | 의미 |
|------|------|
| `pending` (대기) | 아직 작업이 진행 중 |
| `fulfilled` (이행) | 작업이 성공적으로 완료됨 |
| `rejected` (거부) | 작업이 실패함 |

### Promise 기본 구조

```javascript
// Promise 만들기
const myPromise = new Promise((resolve, reject) => {
    const 성공 = true;

    if (성공) {
        resolve("성공 데이터!"); // fulfilled 상태로 전환
    } else {
        reject("에러 발생!");   // rejected 상태로 전환
    }
});

// Promise 사용하기
myPromise
    .then((결과) => {
        console.log(결과); // "성공 데이터!" — resolve 값을 받음
    })
    .catch((에러) => {
        console.error(에러); // "에러 발생!" — reject 값을 받음
    });
```

### 체이닝(Chaining)으로 콜백 지옥 해결

```javascript
// 콜백 지옥을 Promise 체이닝으로 개선
사용자_정보_가져오기(userId)
    .then(user => 레포지토리_가져오기(user.id))
    .then(repos => 첫번째_레포_상세_가져오기(repos[0].id))
    .then(detail => 기여자_가져오기(detail.id))
    .then(contributors => console.log(contributors))
    .catch(error => console.error("어딘가에서 에러 발생:", error));
// 훨씬 읽기 쉬워졌습니다!
```

> 💡 `.then()`은 성공 시, `.catch()`는 실패 시 실행됩니다.

## 4. async / await — Promise를 더 쉽게

`async`/`await`는 Promise를 **동기 코드처럼 읽히게** 만들어주는 문법입니다.  
내부적으로는 Promise를 사용하지만, 훨씬 직관적입니다.

### 기본 규칙

| 키워드 | 역할 |
|--------|------|
| `async` | 함수 앞에 붙여 "이 함수는 비동기 함수입니다"라고 선언 |
| `await` | Promise 앞에 붙여 "여기서 결과를 기다립니다"라고 지시 |

> ⚠️ `await`는 반드시 `async` 함수 안에서만 사용할 수 있습니다.

### Promise 체이닝 vs async/await 비교

```javascript
// ❌ Promise 체이닝 — 중첩이 생기면 여전히 복잡
function fetchData() {
    return fetch("https://api.example.com/data")
        .then(response => response.json())
        .then(data => {
            console.log(data);
        })
        .catch(error => {
            console.error(error);
        });
}

// ✅ async/await — 동기 코드처럼 읽힘
async function fetchData() {
    const response = await fetch("https://api.example.com/data"); // 여기서 기다림
    const data = await response.json(); // 여기서도 기다림
    console.log(data);
}
```

### async 함수의 반환값

`async` 함수는 항상 **Promise를 반환**합니다.

```javascript
async function getNumber() {
    return 42; // 내부적으로 Promise.resolve(42)와 같습니다
}

getNumber().then(n => console.log(n)); // 42
```

## 5. fetch — 서버에서 데이터 가져오기

`fetch()`는 브라우저 내장 함수로, **HTTP 요청을 보내고 응답을 받는** 기능을 합니다.  
Promise를 반환합니다.

### fetch의 2단계 처리

fetch는 응답을 두 번에 나눠서 처리해야 합니다.

```javascript
// 1단계: 서버 연결 및 응답 헤더 수신 → Response 객체
// 2단계: 응답 본문(body) 파싱 → 실제 데이터
async function getData() {
    const response = await fetch("https://api.github.com/users/octocat"); // 1단계
    const data = await response.json();                                    // 2단계
    console.log(data);
}
```

### response.json() vs response.text()

| 메서드 | 사용 상황 |
|--------|-----------|
| `response.json()` | 응답이 JSON 형식일 때 (API 대부분) |
| `response.text()` | 응답이 일반 텍스트일 때 |
| `response.blob()` | 응답이 이미지/파일일 때 |

### 응답 상태 코드 확인

```javascript
async function getData() {
    const response = await fetch("https://api.github.com/users/octocat");

    // response.ok는 상태 코드가 200~299일 때 true
    if (!response.ok) {
        throw new Error(`HTTP 오류! 상태 코드: ${response.status}`);
    }

    const data = await response.json();
    return data;
}
```

### 자주 보는 HTTP 상태 코드

| 코드 | 의미 |
|------|------|
| `200` | 성공 |
| `403` | 권한 없음 (GitHub API 시간당 60회 제한 초과 시) |
| `404` | 찾을 수 없음 |
| `500` | 서버 내부 오류 |

## 6. 에러 처리 — try / catch

비동기 코드에서의 에러는 `try/catch`로 처리합니다.

```javascript
async function fetchUserData() {
    try {
        // try 블록: 에러가 발생할 수 있는 코드
        const response = await fetch("https://api.github.com/users/octocat");

        if (!response.ok) {
            throw new Error(`요청 실패: ${response.status}`);
        }

        const data = await response.json();
        console.log("성공:", data);

    } catch (error) {
        // catch 블록: 에러가 발생했을 때 실행됨
        console.error("에러 발생:", error.message);

    } finally {
        // finally 블록: 성공/실패 관계없이 항상 실행됨 (선택사항)
        console.log("요청 처리 완료");
    }
}
```

### 에러 유형별 처리

```javascript
async function fetchRepos(username) {
    try {
        const response = await fetch(`https://api.github.com/users/${username}/repos`);

        if (response.status === 403) {
            throw new Error("API 호출 한도 초과 (시간당 60회). 잠시 후 다시 시도하세요.");
        }

        if (response.status === 404) {
            throw new Error(`사용자 '${username}'를 찾을 수 없습니다.`);
        }

        if (!response.ok) {
            throw new Error(`알 수 없는 오류: ${response.status}`);
        }

        const repos = await response.json();
        return repos;

    } catch (error) {
        // 네트워크 연결 실패 시에도 catch로 잡힘
        console.error(error.message);
        throw error; // 필요 시 상위로 에러를 다시 던짐
    }
}
```

## 7. 심화: Promise.all — 여러 요청 동시에

여러 비동기 작업을 **동시에 실행**하고 **모두 완료되면** 결과를 받습니다.

### 순차 실행 vs 동시 실행

```javascript
// ❌ 순차 실행 — 총 2초 소요 (1초 + 1초)
async function sequential() {
    const user = await fetchUser();    // 1초 대기
    const repos = await fetchRepos();  // 1초 대기
    return [user, repos];
}

// ✅ 동시 실행 — 총 1초 소요 (동시에 실행)
async function parallel() {
    const [user, repos] = await Promise.all([
        fetchUser(),   // 동시에 시작
        fetchRepos(),  // 동시에 시작
    ]);
    return [user, repos];
}
```

> ⚠️ `Promise.all`은 하나라도 실패하면 전체가 실패(reject)합니다.  
> 일부 실패를 허용하려면 `Promise.allSettled()`를 사용하세요.

## 8. 실전 미션: GitHub API 연동

이제 Codyssey 프로젝트의 **GitHub API 연동 미션**을 구현해봅시다!  
`main-logic.js` 파일 하단의 미완성 부분을 채워나갑니다.

### 미션 요구사항

- `fetch` + `async/await`로 GitHub 레포지토리 목록 API 호출
- `try/catch`로 예외 처리 (403 에러 포함)
- **로딩 / 성공 / 에러 / 빈 상태** UI 분기 처리

### 실제 프로젝트의 HTML 구조

현재 `index.html`의 Projects 섹션은 다음과 같이 구성되어 있습니다.

```html
<!-- index.html — #projects 섹션 -->
<section id="projects" aria-label="GitHub API 연동 카드">
    <h2 class="section-name">Projects</h2>

    <!-- 로딩 / 에러 / 빈 상태를 안내하는 영역 -->
    <div class="projects-status" id="projects-status">
        <div class="spinner"></div>
        <p>Github 프로젝트를 불러오는 중...</p>
    </div>

    <!-- GitHub 레포지토리 카드들이 들어갈 Grid 컨테이너 -->
    <div id="projects-container" class="projects-container"></div>
</section>
```

> **주목할 ID 두 가지**
> - `#projects-status` — 로딩 중 / 에러 / 빈 상태 안내 문구가 표시되는 영역
> - `#projects-container` — 성공 시 카드 목록이 렌더링되는 Grid 컨테이너

### 단계별 구현

#### Step 1 — 기본 fetch 호출

```javascript
const GITHUB_USERNAME = "본인의-깃허브-아이디"; // ← 여기에 본인 ID 입력

async function fetchGithubRepos() {
    const response = await fetch(
        `https://api.github.com/users/${GITHUB_USERNAME}/repos`
    );
    const repos = await response.json();
    console.log(repos); // 콘솔에서 데이터 구조 확인
}

fetchGithubRepos();
```

#### Step 2 — CSS 클래스 방식으로 상태 제어하기

`style.display`를 JS에서 직접 건드리는 대신, **CSS가 스타일을 담당**하고 JS는 클래스만 붙이고 떼는 방식으로 구현합니다.

> **왜 클래스 방식인가?**  
> - 관심사 분리: CSS는 CSS가, JS는 로직만 담당  
> - 나중에 CSS에서 transition 효과를 추가하기 쉬움  
> - 이 프로젝트에서 이미 쓰는 패턴 (`scrollTop.classList.toggle('show', ...)`)과 일치

**먼저 `css/style.css`에 추가:**

```css
/* #projects-status: 기본적으로 숨김 */
#projects-status {
    display: none;
}

/* .show 클래스가 붙으면 보임 */
#projects-status.show {
    display: block;
}
```

**`main-logic.js` 구현 (클래스 방식):**

```javascript
const GITHUB_USERNAME = "본인의-깃허브-아이디"; // ← 여기에 본인 ID 입력

// DOM 요소 선택 — index.html의 ID와 일치해야 합니다
const statusEl    = document.querySelector('#projects-status');    // 상태 안내 영역
const containerEl = document.querySelector('#projects-container'); // 카드 Grid 영역

async function fetchGithubRepos() {
    // 1. 로딩 상태 표시
    statusEl.innerHTML = `
        <div class="spinner"></div>
        <p>Github 프로젝트를 불러오는 중...</p>
    `;
    statusEl.classList.add('show');   // ✅ style.display 대신 클래스 추가
    containerEl.innerHTML = '';       // 이전 카드 초기화

    try {
        const response = await fetch(
            `https://api.github.com/users/${GITHUB_USERNAME}/repos`
        );

        // 2. HTTP 에러 처리
        if (response.status === 403) {
            throw new Error('API 호출 한도 초과 (시간당 60회). 잠시 후 다시 시도하세요.');
        }
        if (!response.ok) {
            throw new Error(`요청 실패: ${response.status}`);
        }

        const repos = await response.json();

        // 3. 로딩 안내 숨기기
        statusEl.classList.remove('show'); // ✅ style.display = 'none' 대신

        // 4. 빈 상태 처리
        if (repos.length === 0) {
            statusEl.innerHTML = '<p>표시할 프로젝트가 없습니다.</p>';
            statusEl.classList.add('show');
            return;
        }

        // 5. 성공 상태 — map으로 카드 렌더링
        containerEl.innerHTML = repos
            .map(repo => `
                <div class="project-card">
                    <h3>${repo.name}</h3>
                    <p>${repo.description || '설명 없음'}</p>
                    <span>⭐ ${repo.stargazers_count}</span>
                    <a href="${repo.html_url}" target="_blank">GitHub 보기</a>
                </div>
            `)
            .join('');

    } catch (error) {
        // 6. 에러 상태 처리
        statusEl.innerHTML = `
            <p>프로젝트를 불러올 수 없습니다.</p>
            <button id="retry-btn">다시 시도</button>
        `;
        statusEl.classList.add('show'); // ✅ 클래스 방식
        console.error('레포지토리 로드 실패:', error.message);

        // 7. [다시 시도] 버튼 이벤트 — 에러 UI가 렌더링된 뒤 연결
        document.querySelector('#retry-btn')
            .addEventListener('click', fetchGithubRepos);
    }
}

// 페이지 로드 시 실행
fetchGithubRepos();
```

> ⚠️ `#retry-btn`은 에러 발생 시에만 동적으로 생성되므로,  
> `catch` 블록 안에서 `addEventListener`를 연결해야 합니다.

### API 응답 데이터 구조 미리보기

```json
[
    {
        "name": "my-project",
        "description": "프로젝트 설명",
        "html_url": "https://github.com/username/my-project",
        "stargazers_count": 5,
        "language": "JavaScript",
        "updated_at": "2024-01-15T09:00:00Z"
    }
]
```

## 전체 개념 정리

```
동기(Sync)      → 코드가 순서대로 실행, 앞 코드가 끝나야 다음 실행
     ↓ 문제: 기다리는 동안 화면이 멈춤
비동기(Async)   → 기다리는 동안 다른 코드 실행
     ↓ 해결책 1
콜백(Callback)  → 완료 시 호출할 함수를 미리 전달
     ↓ 문제: 중첩이 깊어지면 콜백 지옥
Promise         → 미래 값을 담는 그릇, .then()/.catch()로 처리
     ↓ 개선
async/await     → Promise를 동기 코드처럼 읽히게 만드는 문법
     +
fetch()         → 서버에 HTTP 요청을 보내는 브라우저 내장 함수
     +
try/catch       → 비동기 코드의 에러를 잡는 구문
```

## 자주 하는 실수 모음

### ❌ await 없이 Promise 사용

```javascript
async function wrong() {
    const response = fetch("https://api.github.com/users/octocat"); // await 빠짐!
    const data = response.json(); // response가 Promise 객체라 .json()이 없음 → 에러
}
```

### ✅ 올바른 사용

```javascript
async function correct() {
    const response = await fetch("https://api.github.com/users/octocat"); // ✅
    const data = await response.json(); // ✅
}
```

---

### ❌ async 없는 함수에서 await 사용

```javascript
function wrong() {
    const data = await fetch("..."); // SyntaxError! async 함수가 아님
}
```

### ✅ 올바른 사용

```javascript
async function correct() { // ✅ async 필수
    const data = await fetch("...");
}
```

---

### ❌ response.ok 확인 안 함

```javascript
async function wrong() {
    const response = await fetch("https://api.github.com/users/없는유저");
    const data = await response.json(); // 404여도 에러 없이 { message: "Not Found" } 반환
    console.log(data.name); // undefined → 원인 파악 어려움
}
```

### ✅ 항상 응답 상태 확인

```javascript
async function correct() {
    const response = await fetch("https://api.github.com/users/없는유저");
    if (!response.ok) throw new Error(`${response.status} 오류`); // ✅
    const data = await response.json();
}
```
